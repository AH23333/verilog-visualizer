## 2. R113 核心结论（接手前必读，防止改回去）

### 镜像语义（`src/lib/cellMirror.ts`）

- **mirror 存器件本地轴**；`applyMirror` **完全不读 angle**（旧实现的
  `swap = angle===90||270` 换轴是组合操作全面崩的病根——每转一次镜像轴就被重新解释一次）。
- **屏幕镜像 ≡ 本地轴取反 + 角度取反**（推导：`M_h·R(θ)·L = R(−θ)·M_h·L`），
  对任意 θ 成立，**无 90°/270° 特判**。
- `flipCell` 承担角度取反 `c.rotate(-2*a)`——⚠ **joint 的 `rotate(deg)` 实际轨道量是
  `angle + deg`**，要得到 `−a` 必须传 `−2a`。
- **旋转路径绝不能再调 `applyMirror`**（`rotateSelection` 里的重挂已删）。
  在新语义下重挂虽是幂等无害（等价变异），但保留它会诱使后人恢复换轴逻辑。
- 单选与多选走同一个 `flipCell`；多选**绝不能**再 `rotate(-2a)`（取反两遍≡没取反）。

### 多选几何（实测结论，别再质疑）

- `c.getBBox()` **不随 angle 变化**（恒 = pos+size）；`c.rotate(deg)` **位置纹丝不动**
  ⇒ **bbox 中心就是 joint 的旋转中心**，多选旋转/镜像的几何算法本来正确，R112 曾怀疑
  它有偏移——实测否掉，别按那个怀疑去改。

### 存档迁移

- `MIRROR_VER_LOCAL = 2` 单点定义于 `cellMirror.ts`，序列化侧与载入侧共用；
  旧存档（无标记）按 angle 迁移（90/270 的 h/v 对调，0/180 不动），新存档写 `mirrorVer: 2` 幂等。

## 4. 本批踩过的坑（教训已固化，接手前过一遍）

1. **跑 UI 闸门期间绝对不能改 `src/`** —— Vite HMR 重载页面，`window.__sandboxPaper`
   直接变 undefined，前后两次结果不一致。源码一次改完 + tsc 通过，再跑干净的闸门。
2. **自造回归：`menuClick` 的两种调用约定** —— `at` 传坐标＝自己右键开菜单；
   **第三参省略（null）＝菜单已开着，只负责点那一项**（两级菜单）。给前者加的
   无条件 `Escape` 收尾把后者点坏了（r24 变红）。已修：`at === null` 只点不 Escape。
   **给共用夹具加「更保险」逻辑前，先枚举全部调用点的参数形态。**
3. **UI 夹具「元素应该存在」的判断一律 `waitFor`，不许 `count()`** ——
   vite 冷启动 React 挂载比固定 settle 晚，`count()` 把「启动慢」报成「活动栏没有 X 按钮」。
4. **判据必须查角度** —— 多选镜像只判位置/撤销时，角度取反两遍的缺陷一路绿灯穿过
   （形状镜像仍生效、位置仍对称、撤销也退得回去，只有角度停在原值）。
5. **右键菜单要每次现取屏幕坐标**；复位走真实菜单往返（只 `prop('mirror',null)`
   不会复原 body transform/端口几何，后续全是脏读数）。
6. **`page.evaluate` 拿不到 Node 侧闭包**——归一化函数要在回调内部重写。
7. **长跑批（几十格×百分钟）里的红一大半是资源耗尽**——ENVRED ≠ RED，必须逐格单跑复核。
   `vite build` 失败先手动 build 一次再复跑，别误判成构建坏了。
8. **判据坐标系**：`getBBox()` 是未旋转模型盒；`size` 不含引脚（And 60×32 但 DOM 106×32）；
   And 宽 60 时 `left/dx:30`↔`right/dx:-30` 锚点恰好都是 x=30，别拿它当「翻转生效」的证据。
